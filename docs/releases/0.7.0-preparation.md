# ComfyGit 0.7.0 release preparation

Status: locally validated candidate; publication is a separate action.

This release lets an environment declare required or optional models independently
of saved workflows. Dynamic applications can now materialize their complete model
requirements from `pyproject.toml`. Readiness, inventory, missing-model detection,
source enrichment, and orphan cleanup retain those declarations. Requested model
acquisition failures prevent materialization from being marked complete. Existing
catalog entries without explicit criticality retain workflow-derived semantics.

Custom-node clones initialize recursive submodules at their parent-pinned commits.
An incomplete or mismatched cached submodule checkout is rejected and refreshed.
This prevents a pinned node from silently fetching mutable fallback code at startup.
The node-specific cache accessor is named `get_cached_node_path`; the inherited
string-key cache accessor retains the base interface.

Workflow contracts accept native ComfyUI `3d` file outputs, allowing built-in
`SaveGLB` without an unpublished application exporter. Duplicate `files` / `3d`
entries are emitted once. Materialize progress says models are available because
successful acquisition may reuse existing indexed bytes.

Normative clauses: `CGCORE-DEP-02C`, `CGSPEC-MODEL-03B`, `CGSYNC-NODE-00`,
and the native artifact-output guarantee in the core contract.

## Workflow and installation hardening

Workflow resolution now supports explicit custom-node mappings and strict JSON
completion reports for automation. Null optional workflow definitions load
correctly. Environment-scoped runtime status and restart verify the managed
runtime identity, readiness and queue before accepting a restart.

Core supports explicit per-process credential overrides and anonymous access,
provider environment variables and existing provider logins. OS keyring storage
is an optional core extra; the CLI installs it for interactive credential storage.
Python 3.10 installations include the required tomli compatibility dependency.
The repository bundles a reusable ComfyGit skill and generic source-install
instructions without private host paths.

Release validation includes clean wheel installation on Python 3.10 and 3.12,
core-only operation without keyring, and CLI behavior without an OS keyring
backend. CI additionally runs clean-install checks on macOS and Windows.

## Publication sequence

1. Review and publish this candidate through the existing main-branch workflow.
2. Confirm `comfygit-core==0.7.0`, then `comfygit-studio==0.7.0`, then
   `comfygit==0.7.0` are visible on PyPI. The workflow owns this ordering.
3. Confirm the Splat Smith ComfyGit source pin is publicly fetchable before its
   launcher release. Its local-source staging override supports review beforehand.
4. Prepare Manager's exact core/Studio pins only after PyPI publication.

Linux source validation does not certify Windows/macOS installers, Splat Smith
Wan generation, SplatKit training, or the desktop launcher's complete install/update
journey. Those remain application release gates. Shared app configuration is
an independent adapter above ComfyGit and is not shipped in these Python packages.
